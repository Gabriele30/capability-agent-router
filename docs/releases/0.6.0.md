# CAR 0.6.0 — Draft release notes

This is a release-notes draft for the audited 0.6.0 scope. It is not a published
release and does not create a Git tag.

## Highlights

- Experimental controlled Codex writes after a verified Gemini-to-Codex failure.
- Explicit per-invocation write consent and repository-relative file scope through
  `car execute`.
- Exact source baseline capture, isolated Git worktree projection, strict delta
  validation, transactional source application, and verification-gated finalization.

## Safety model

Codex writes only in a CAR-owned isolated workspace. CAR treats the resulting delta
as untrusted, rejects unexpected or unsupported changes, and never accepts a change
from process success alone. Only a finalized CAR verification result can accept source
changes. Authorization is distinct from routing and is never persisted.

## CLI controlled write

Controlled write is disabled by default and currently requires an eligible verified
`GEMINI_TO_CODEX` failure, local `codex_write.enabled=true`, normal `car execute`
confirmation, `--allow-codex-write`, explicit `--codex-write-path` values, and a
CAR-selected verification plan. Direct `CODEX` routes do not write.

## Verification and rollback

Source application is transactional. CAR revalidates source and isolated identities
before application, verifies the source through allowlisted commands, checks integrity
again, then finalizes or performs identity-aware rollback. Git HEAD, branch, and index
are preserved.

## Windows support

On Windows the controlled runtime uses the unelevated Codex sandbox backend and prepares
ACLs only on its CAR-owned temporary worktree parent. Source repository ACLs are never
modified.

## Testing

The controlled pipeline has offline coverage plus separate opt-in live validations for
the internal Gemini-to-controlled-Codex chain and the real `car execute` path. Both
canonical live validations have been manually observed as passed on synthetic Git
repositories.

## Known limitations

- Experimental feature, disabled by default.
- Explicit existing-file paths only; no directory or glob authorization.
- DELETE, RENAME, symlink, protected-path, and binary changes fail closed.
- Direct `CODEX` routes do not use controlled write.
- Gemini configuration and local Codex CLI authentication are required for live use.
- CAR claims write confinement, not host-wide read isolation.
